## Improvement notes (not filed) / 改进点（未提 issue）

- Default face refuses named `let`, `while`, `do`, `random`, `exact->inexact` with "tree-walker fallback forbidden in production pipeline (#2213)". At `f093a8887` a plain unbound variable on the Soft face reports `unbound variable: x` with a "did you mean" hint and exit code 1, but on the default face `(let ((s "7")) (* s 2))` still reports only the #2213 message.
- Restricted (default sandbox) denies `vector-set!` without a Mutate grant, but the denial is silent: `(display (vector-set! v 1 7))` prints `<unknown>`, the vector is unchanged, and the run exits 0. Numeric code computes wrong answers with no warning.
- Errors from primitives display as `<unknown>` and do not stop the program or change the exit code. There is no `exit` primitive, so test runners must grep for `FAIL`.
- Missing common Scheme procedures (number conversions and `eqv?` / `memv` / `assv` are in #4469 / #4470): `do`, `case`, `vector-fill!`, `vector-map`, `vector-copy`, `assoc`, `assq`, `string->symbol`, `symbol->string`, `let-values`, `iota`, `exit`, and SRFI-69 hash tables (`make-hash-table`).
- Out-of-range `vector-ref` is inconsistent: index 5 on a 3-vector returns `<error>`, index −1 returns `<unknown>`; neither stops the program.
- `(/ 7 2)` → `3` (integer division) while `(/ 7.0 2)` → `3.5`. Averages need an explicit `(* 1.0 x)`.
- Build type: Aura's `CMakeLists.txt` does not default `CMAKE_BUILD_TYPE`, so `cmake -B build` produces an unoptimized binary. The speed figures in the next notes and the Chapter 2–8 wall times come from such a build; a RelWithDebInfo build of the same commit runs the RL drivers 3–5× faster (an empty 10 000-iteration loop: 373 ms → 106 ms with the std prelude loaded; a mountain-car Sarsa step about 5 ms → 1 ms). A default build type (or a warning) would avoid accidental benchmarks of `-O0` code.
- Soft interpreter speed (unoptimized build): about 40 µs per simple loop iteration and about 2 ms per bandit step (10 arms). That is why Ch2 defaults to 20 runs × 300 steps. A call to a 4-iteration max-over-a-vector helper costs about 240 µs (200 000 calls in 48–51 s), so tabular control spends most of its time in `max` / `argmax` over 4 actions: cliff walking runs at about 40 ms per episode, and the Fig 6.3 α sweep (18 configurations) takes 13 min at 4 runs × 100 episodes.
- Named-`let` memory (#4459) shapes the code: 200 000 calls of a helper whose loop is a named `let` peak at 328 MB; the same helper written as a top-level recursive procedure peaks at 111 MB. `lib/algos/td.aura` and `lib/algos/nstep.aura` use top-level recursion for the per-step helpers (`q-max`, `q-argmax-tie!`, return sums, Tree Backup) for that reason.
- File mode echoes the value of the last top-level form (a trailing `#t` / `#f` after program output).
- Numeric literals: `.5` and `-.5` are parse errors ("expected expression, got '.'"), `+5` is an unbound variable, `1.` is a parse error and `#x1F` / `#e1.5` are not read. `1/2` is read as two tokens, `1` and the symbol `/2`, so `(quote (1/2 3))` silently gives `(1 /2 3)`. Code here writes `0.5`, `5`, `1.0`.
- `(vector-ref v "1")` (string index) aborts with SIGABRT, like the float index of #4456; both come from the unchecked index in `vector-ref`.
- `case` and `exact` / `exact?` / `eqv?` are unbound (in addition to the list above). `cond` and `let*` keep tail calls (200 000-iteration loops run); only `when` / `unless` / `and` / `or` do not (#4454).
- Long runs keep growing even with no closure created per step: the Chapter 8 changing-maze driver went from 274 MB to 340 MB RSS between minutes 3 and 5, and the off-policy Chapter 7 driver reached 444 MB. File mode never runs `compact_sweep` (#4459), so every cons and boxed float of a run stays allocated.
- Speed for planning: one Dyna planning update (two PRNG draws, a 4-action max, one vector update) costs roughly 0.4 ms on the Soft face, so Figure 8.2 runs with 2 runs instead of 30 (147 s) and Figures 8.4–8.5 with 3 runs (440 s).
- `AURA_SANDBOX=strict` fails while loading the std prelude ("Soft oneshot std prelude failed … tree-walker fallback forbidden").

- Chapter 9–10 speed (RelWithDebInfo, `5cc915687`): a 1000-state walk step with one tile lookup and one update is about 0.1 ms, a 10-tiling step about 0.4 ms, and a mountain-car Sarsa step (8 tilings × 3 actions) about 1 ms. Fig 9.10 at the book's 5 000 episodes takes 6.5 min with 10 tilings; 50 tilings would take about 30 min.
- Internal `define` after an expression in a body (`(define (f) (display "x") (define (h) 1) (h))`) works, and an internal define doing `set!` on an outer `let` variable gives the right result at `5cc915687` (the #4350 `set!` breakage is fixed).
- Chapter 9–12 loop cost (RelWithDebInfo, `5cc915687`, std prelude loaded): one iteration of a vector-scaling loop costs about 17 µs written as top-level recursion and about 11 µs as a named `let` or a `while` with a `(begin …)` body. Every inner loop over features pays this, so the Fig 9.5 order-20 bases take about 1 ms per gradient MC update, a Sarsa(λ) step with about 350 live traces 4–6 ms, and a differential-Sarsa access-control step 0.3 ms (2 million steps would take 10 min). #4464 (per-call cost linear in the number of globals) is part of the recursion cost.
- Float overflow is IEEE: a diverging TD(λ) run reaches `inf` / `nan` without an error, which is what the error tables need (they cap at 1.0; `(< nan 1.0)` is `#f`).
- `expt` with a negative exponent never returned at `3034d4723` (#4458, fixed at `110d8fb49`); Chapter 13 and Fig 2.6 now use `(expt 2.0 k)`.
- Gap-fill speed (RelWithDebInfo, `3034d4723`): a bandit step costs about 0.6 ms, so Fig 2.6 (26 points) takes 2.5 min at 10 runs and 13 min at 50. One inner multiply-add of the car-rental sweep (top-level recursion over a vector) costs about 17 µs, so a 441-state synchronous sweep with the factorized model (18 500 products) takes 0.32 s and policy iteration (356 sweeps) 115 s; the unfactorized sum over requests and returns would be about 40× slower. The Fig 8.8 driver spends most of its time in policy evaluation of 1000 states (about 0.1–2 s per evaluation point, warm-started).
- Seeding: our Park–Miller generator seeded with consecutive integers gives nearly equal first uniforms (the gap is 16807 / (2^31 − 1) ≈ 8e-6 and grows ×16807 per draw). The Fig 2.6 driver seeds run r with `seed + r` for common random numbers, so it discards four draws after seeding. This is a property of the LCG in `lib/rl/rng.aura`, not an Aura bug.
- `assq` / `assoc` are still unbound (`did you mean 'asin'?`); `apply`, `length`, `list-tail`, `vector->list`, `list->vector` and `letrec` work. `(min 1 2.0)` → `1` (R7RS: `1.0`, inexact contagion).
